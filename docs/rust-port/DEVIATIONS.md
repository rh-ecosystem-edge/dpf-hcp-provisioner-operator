# Rust port — known deviations from the Go implementation

The port targets 100% behavioural compatibility. Byte-level equivalence with the Go code is
enforced by golden fixtures generated from the Go sources for everything the operator writes:
objects sent to the API server, ignition payloads (incl. gzip bytes), DPUServiceTemplate helm
values, condition/event/error strings, CLI usage/errors and log lines. An end-to-end
differential run of the Go and Rust `manager` binaries against the same envtest API server
produced identical CR status (`crates/manager/tests/smoke.rs` with
`SMOKE_MANAGER_BIN=<go binary>`).

The Go implementation and its golden generators (`hack/golden/*`) have since been removed. The
fixtures under `crates/*/tests/fixtures/` are kept as **frozen references** of the Go
behaviour: they can no longer be regenerated, and any intentional change to them is a new
deviation that must be listed here. (A Go binary for the differential smoke run can still be
built from the git history, commit `fead352`.)

The remaining differences are listed below. None changes reconciliation results; most are
unreachable in practice or only affect diagnostic text.

## Process / runtime

| Area | Go | Rust | Impact |
|---|---|---|---|
| Stack traces in error logs | Go frames | Rust frames (same zap layout) | log text only |
| Go runtime metrics (`go_*`) | exported | not exported (process_* and all controller-runtime/workqueue/rest-client metrics are) | metrics only |
| Metrics self-signed cert key | RSA-2048 | ECDSA P-256 (ring cannot generate RSA) | none (same CN/SANs/validity) |
| Metrics endpoint content types | text/protobuf negotiation | always text format | protobuf scrapers fall back to text |
| Network error wording | Go `net` errors | Go-like mapping for common cases (refused, reset, TLS unknown authority/hostname, DNS, timeouts); rare errors keep the Rust wording | condition/log text on network failures |
| Registry/HTTP calls | cancelled via `ctx` | cancelled on drop; registry calls have no ctx | none for reconcile results |
| Cached list ordering | random map order | deterministic (namespace, name) | none |
| Webhook server | constructed, never started (no webhooks) | not constructed; cert watcher still validated/started as in Go | none |
| Unknown fields on read-modify-write | dropped (Go structs) | preserved (`extra` maps) | safer; ignition DPUFlavor output clears them to match Go bytes |

## Library-level behaviour

| Area | Difference |
|---|---|
| `equality.Semantic` | implemented on JSON documents with nil≡empty normalisation; a nil pointer-to-struct and a pointer to an all-`omitempty` empty struct compare equal |
| Map-iteration-dependent messages | where Go picks a "random" element (status mirror append order, CSR missing-usage message, ignition partition collisions), Rust uses a stable order |
| Nil-pointer panics in Go | reproduced: the reconciler re-raises Go's `runtime error: invalid memory address or nil pointer dereference`, recovered by the runtime exactly like controller-runtime (`panic: … [recovered]`) |
| `resource.MustParse` panic on invalid hugepage size | returns an error with the same message (unreachable: CRD enum restricts the value) |
| Kubeconfig parse errors | kube-rs wording instead of clientcmd wording |
| YAML parsing | `gocompat::yaml` parses what yaml.v2 emits + JSON; anchors/tags/multi-doc are rejected (only used in tests) |
| x509 edge cases | invalid UTCTime/GeneralizedTime subject values: same accept/reject decisions, different error wording (logs only) |
| Ignition validation | Go reports the first of several colliding partition numbers in map order; Rust reports the first in document order |

## Build / CI

* `Containerfile` builds on `registry.access.redhat.com/ubi10/ubi` with the UBI Rust toolchain
  (Rust 1.92, the workspace `rust-version`) and links glibc statically (`glibc-static`,
  `-C target-feature=+crt-static`), producing a static-pie `manager`; the runtime image is
  unchanged (`ubi10-micro`). `make build` produces a static musl binary instead, which needs no
  extra system packages on developer machines.
* Hermetic Konflux builds prefetch the builder RPMs (`rpm-prefetching/`, lockfile generated by
  `rpm-prefetching/generate-lock.sh` with dnf in UBI10) and the Cargo dependencies
  (`.tekton/dpf-hcp-provisioner-rhel10-operator-*.yaml`). Needs validation in a Konflux run.
* OpenShift CI (`lint`, `unit-tests`) still uses the Go build root from `.ci-operator.yaml`;
  the Makefile installs the pinned Rust toolchain into `bin/` when `cargo` is missing, so
  `make lint`/`make test` run there unchanged. `hack/ci/build-root.Containerfile` is a UBI10
  build root with Rust for a future `build_root.project_image` switch in openshift/release.
* `verify-deps`: the shared `go-verify-deps` CI step skips repositories without `go.mod`;
  `make verify-deps` is the Cargo counterpart (lockfile in sync, all locked dependencies resolve
  and build offline) and runs as part of `make lint`.
* With the Go API types gone, the operator's CRDs (`config/crd/bases`) and RBAC
  (`config/rbac/role.yaml`) are hand-maintained sources (they were last generated by
  controller-gen from the Go markers and are unchanged). `make manifests` only syncs the Helm
  RBAC templates; the Rust types of the own API (`crates/apis/src/provisioning_types.rs`) are
  kept in sync with the CRDs by hand.
* External CRDs (DPF, HyperShift, OpenShift config) are checked in (`config/crd/external`,
  `test/e2e/testdata/crds`) instead of being generated from `vendor/` at test time; they and
  `crates/apis/src/generated` are regenerated by `make generate` from the standalone Go module
  `hack/gen-rust-apis` (upstream versions pinned in its `go.mod`, identical to the former root
  `go.mod`).
